Day 23:  RDS Security and Management

1. Security Groups and Parameter Groups

What are Security Groups?

Security Groups act as virtual firewalls for your RDS instances, controlling inbound and outbound network traffic.
They allow you to specify which IP addresses or EC2 instances can access your RDS instance.
By default, all inbound traffic is denied, and all outbound traffic is allowed.

Key Concepts:
Inbound Rules: Define who can access the RDS instance (e.g., specific IP ranges or EC2 instances).
Outbound Rules: Define where the RDS instance can send traffic (e.g., for replication or external services).

Best Practices:
Restrict access to only trusted IP addresses or EC2 instances.
Use separate security groups for different environments (e.g., production, staging).

What are Parameter Groups?

Parameter Groups are containers for database engine configuration values.
They allow you to customize settings like memory allocation, query timeouts, and more.
RDS provides default parameter groups, but you can create custom ones to meet specific requirements.

Key Concepts:
Static Parameters: Require a database reboot to take effect.
Dynamic Parameters: Take effect immediately or after the next maintenance window.

Best Practices:
Create custom parameter groups for each RDS instance to avoid conflicts.
Test parameter changes in a staging environment before applying them to production.

2. Database Backups and Recovery

What are Automated Backups?

RDS automatically backs up your database during a specified backup window.
Backups are retained for a configurable period (1–35 days).
Automated backups include the entire database and transaction logs, enabling point-in-time recovery.

Key Features:
Backup Window: Define a time when backups occur (e.g., during low traffic hours).
Retention Period: Set how long backups are retaine

What are Manual Snapshots?

Manual snapshots are user-initiated backups of your RDS instance.
Unlike automated backups, manual snapshots are retained until you delete them.
Useful for long-term retention or before making major changes.

Key Features:
On-Demand: Create snapshots whenever needed.
Cross-Region Copy: Copy snapshots to another region for disaster recovery.

Restoring from Backups or Snapshots

Restoring from Automated Backups:
You can restore to any point in time within the retention period.
RDS creates a new instance with the restored data.

Restoring from Manual Snapshots:
Create a new RDS instance from the snapshot.
Useful for cloning databases or recovering from failures.

3. Hands-on:
Configure security groups for your RDS instance.
Create a parameter group and modify database parameters.
Take a manual snapshot of your RDS instance and restore from it.
